## 2. Proposed folders and source-to-destination mapping

Smallest structure that satisfies the repo convention and the audit's recommendations.

```
catalogue-assets/                         ← NEW, gitignored (needs one line in .gitignore); never under public/
  full-brogue-wingtip/                    ← copies of the chosen files, original filenames kept
  spectator-brogue/

public/images/products/                   ← existing, flat; existing files untouched
  full-brogue-wingtip/
    brown-hero.webp
    brown-top.webp
    brown-side.webp
  spectator-brogue/
    white-black-hero.webp
    white-black-top.webp
    white-black-sole.webp
    white-brown-hero.webp
    white-brown-top.webp

catalogue-review/
  image-provenance.md                     ← NEW, tracked: one short table, one row per published image
```

Decisions behind it:
- **No `originals/`, `background-edits/`, `ai-colourways/` subfolders.** With so few files each, they would be nearly empty. Original filenames (`PXL_…`, `… (Product Beautifier)`) already show the kind of file.
- **Per-product subfolder in `public/`**, not the existing flat style, because each product now has several images and the filenames would otherwise collide or become long. Existing products stay flat and untouched.
- **Roles live in data, not folders.** No `gallery/` or `colourways/` folders; the product entry will say which file is the hero and which is a colour variant.
- **Collages and unselected files stay in `~/Documents/Shoes`**, unless you want them copied into `catalogue-assets/` too (Decision 6).
- **Provenance note format** (one row per published image): destination file · source file (original path) · kind (`photograph` / `ai-concept`) · who edited it (PhotoRoom/none) · approved by · date. This is a tracked, tiny Markdown file, which is the "small, maintained note" you asked for.
- **Export spec:** WebP, long edge 1600 px (card shows at most ~500 CSS px, so 1600 covers 2× and zoom), roughly 100–250 KB each. `next/image` resizes on request. Keep the 2400-px edits in `catalogue-assets/` as masters.

Referencing in code (later, in `src/data/portfolio.ts`): `image: "/images/products/spectator-brogue/white-black-hero.webp"`, as the six existing entries do. The additional views and the second colourway would use the additive `gallery` / `colourways` fields proposed in the audit (§4).
